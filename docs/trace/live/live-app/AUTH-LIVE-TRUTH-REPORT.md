## 2. Auth contract — verified facts (grade P: live probe + source)

- Launch token is generated by the launcher, stored at `<dataDir>/launch.token` (32 chars),
  exported to the child as `HIVEROUTER_LAUNCH_TOKEN`, and handed to the browser as
  `/?launch=<token>` (`tools/start-hivemind.ps1:17-40,113`).
- The web app reads `?launch=` (`web/src/main.tsx:12-40`, `web/src/api/client.ts:284-305`)
  and sends it as `x-hivemind-launch` on same-origin `/api/*` reads.
- Server refuses unauthenticated `/api/*` GETs with **403 `E_ORIGIN_REJECTED`**
  (`backend/crates/hiverouter-core/src/http.rs` — `mutation_auth` for read routes,
  `session` handler for `/api/session`).
- `/ws?token=<session>&last_seq=<n>` is authenticated by the **session token**, not the
  launch token; a context that cannot read `/api/session` never opens the socket.
- Live probes (no secret printed):

| Probe | Observed |
|---|---|
| `GET /api/session` no header | 403 `{"code":"E_ORIGIN_REJECTED","message":"the launcher token is required to read the session"}` |
| `GET /api/session` forged token | 403, same body |
| `GET /api/session` launcher token | 200 `{schema:"hiverouter.v1", last_seq:1706, ws:"/ws", token:present}` |
| `GET /api/logs?source=stdout&tail=1` no header | 403 `"this read route requires the launcher token"` |

New harness: `e2e/helpers/app-auth.ts` — resolves the token from `E2E_LAUNCH_TOKEN`, else
`launch.token` under `E2E_DATA_DIR` / `HIVEROUTER_DATA_DIR` / `%LOCALAPPDATA%\HiveMind`;
`gotoWithLaunch()`, `probeSession()`, `assertStrictLaunchAuth()`, and redaction helpers.
It fails **loudly** (`LIVE_LAUNCH_TOKEN_MISSING` / `LIVE_LAUNCH_TOKEN_REFUSED`) instead of
navigating unauthenticated. Evidence: `docs/trace/live/live-app/16-auth-gate.json`,
`17-auth-positive.json`, `18-auth-missing-token.json`, `19-auth-invalid-token.json`.

New negative tests (all pass): missing token → 403 + refusal banner + **0 WebSockets**;
invalid token → same; plus the HTTP gate for `/api/session` and `/api/logs`.
